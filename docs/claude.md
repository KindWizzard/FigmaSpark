# FigmaSpark в Claude

Вставленная ссылка сама по себе не добавляет Claude локальные инструменты. Есть два локальных способа подключения.

## Claude Code и режим Code приложения

Используйте терминал Claude Code, расширение редактора или режим **Code** в приложении Claude. Нужен локальный сеанс на том же компьютере, где запущены Figma и мост.

```sh
npm run install-skill -- --editor claude
npm run service -- start
```

Перезапустите плагин FigmaSpark в нужном файле, нажмите на маскота и вставьте свежую инструкцию в сеанс Code. Она просит получить `/connect` через локальный терминал (`curl`), а затем начать с `overview`. Облачный WebFetch для localhost не подходит.

## Обычный Chat в Claude Desktop

Однократно установите локальный адаптер из папки FigmaSpark:

```sh
npm run install-claude
```

Он добавляет `figma-spark` в `claude_desktop_config.json`, сохраняя остальные настройки и резервную копию в `.runtime/claude-backups/`. В конфигурацию записываются только executable, путь адаптера и путь локальной конфигурации, без токена. Другую существующую настройку с тем же именем можно заменить через `npm run install-claude -- --update`.

Полностью закройте и снова откройте Claude, когда текущие задачи завершены. Проверьте наличие локального сервера `figma-spark` в настройках разработчика и доступность инструментов в Chat. Интерфейс Claude может запросить разрешение на их использование.

После этого вставьте свежую инструкцию с маскота. Claude должен вызвать:

1. `figma_spark_connect` с `url` из инструкции. Ответ включает скилл, подключённые файлы и выбранный `sessionId`.
2. `figma_spark_read` с `command: "overview"` и этим `sessionId`.
3. По задаче — scoped `search`, компактный `snapshot` или `figma_spark_image` для выбранных node IDs.

Этот адаптер использует MCP stdio для входа из Claude. Он не обращается к стандартному Figma MCP: данные идут через тот же локальный HTTP JSON → постоянный WebSocket → Figma Plugin API. В адаптере только три инструмента для чтения. `patch`, произвольный JavaScript и shell через него недоступны.

## Сайт claude.ai

Удалённые инструменты сайта не видят localhost вашего Mac. Установка локального скилла и вставление ссылки этого не меняют. Для текущей архитектуры используйте Code на этом компьютере или Chat в Desktop с локальным адаптером. Публичный relay или tunnel этим проектом не устанавливается.

Это ограничение описано в [документации локальных и удалённых подключений Claude](https://support.claude.com/en/articles/11725091-when-to-use-desktop-and-web-connectors) и [сетевых требованиях удалённых коннекторов](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp).

## Диагностика

| Что произошло | Что проверить |
| --- | --- |
| `Connection refused` | `npm run service -- start`, затем `npm run service -- status`. |
| Claude пишет, что localhost недоступен | Используется облачный WebFetch или Chat без локального адаптера. Переключитесь в локальный Code либо настройте Desktop. |
| `figma_spark_connect` не появился | Проверьте установку и полностью перезапустите Claude после завершения текущих задач. |
| Файл не подключён | Откройте FigmaSpark в нужном Design-файле. Маскот должен показывать связь. |
| Старая сессия | Нажмите на маскота ещё раз после переподключения. Не выбирайте другой файл автоматически. |
| Несколько файлов | Выберите нужный `sessionId` из подключения и передавайте его в каждом запросе. |

`npm run service -- start` оставляет процесс в фоне. Проверка: `npm run service -- status`; перезапуск: `npm run service -- restart`; остановка: `npm run service -- stop`. После перезагрузки компьютера сервис нужно запустить снова; Desktop-адаптер делает это при первом обращении. Логи остаются в `.runtime/bridge.log`.
