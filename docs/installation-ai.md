# Установка FigmaSpark через ИИ

Эта инструкция предназначена для локального агента с доступом к файлам, терминалу и, по возможности, Figma Desktop. Источник: https://github.com/KindWizzard/FigmaSpark.

## Если плагин уже открыт

1. Получи URL `/connect`, скопированный по клику на маскоте. Отсутствующий URL по умолчанию: `http://127.0.0.1:3847/connect`.
2. Прочитай Markdown по ссылке и актуальный `SKILL.md`, который она указывает. `?format=json` возвращает те же сведения в структуре: расположение CLI, конфигурации, установщика, скилла, команды и сессия.
3. Установка разрешена, когда пользователь попросил установить скилл или вставил скопированный запрос на установку. Определи текущий редактор и запусти его профиль: `node <project>/scripts/install-skill.mjs --editor codex|cursor|claude`. Не устанавливай сразу во все редакторы. Для другого редактора найди его поддерживаемую папку Agent Skills и используй `--dest <папка>/figma-spark`. Если установка не разрешена, предложи её и работай по загруженной инструкции в текущей задаче.
4. Если скилл уже есть, проверь существующую установку. Для разрешённого обновления используй `--update`; установщик сохраняет старую папку в `.runtime/skill-backups/`. Не создавай дубликат в другом месте. Не меняй настройки редактора и посторонние скиллы.
5. Запусти `node <project>/scripts/spark.mjs connect <LOCAL_URL>`. Подтверди, что выбрана нужная сессия; после переподключения старый ID может стать недействительным. Тогда выбери файл через авторизованный `status` по задаче пользователя.
6. Начни с `overview`, затем сузь чтение через поиск и node IDs. Для сверки требуется документация, указанная пользователем. Не утверждай соответствие ТЗ, которое не предоставлено.

## Чистая установка

1. Выбери постоянную папку проекта. Склонируй репозиторий и прочитай README, затем установи зависимости через `npm ci`. Нужен Node.js 22+.
2. Создай собственную регистрацию Figma Desktop → Plugins → Development → New plugin, Figma Design, с UI. Figma выдаст `manifest.json` с `id`. Это одноразовый шаг для данного пользователя.
3. Выполни `npm run setup -- --plugin-id ID`, или передай созданный manifest через `--manifest PATH`. Если в этой копии уже есть валидный локальный manifest, `npm run setup` сохранит текущий ID. ID другой копии не выдумывай.
4. Импортируй получившийся `FigmaSpark/plugin/manifest.json` через Import plugin from manifest. Запусти `npm start` как долгоживущий локальный процесс и открой FigmaSpark → Подключиться в тестовом Design-файле.
5. Установи скилл только в текущий редактор пользователя. При отсутствии управления Figma подготовь все файлы и сервис и попроси пользователя выполнить конкретный оставшийся шаг регистрации/импорта. Не выдавай подготовку за установленный плагин.
6. Проверь `/health`, живой `connect`, `overview`, поиск известного текста и компактный snapshot тестового фрейма. Плагин должен быть в режиме чтения. Скопированная инструкция должна вести на работающий локальный `/connect`, а сессия — на нужный файл.
7. Сообщи путь к проекту и установленному скиллу и оставь сервис запущенным. Пользователь запускает плагин в нужном макете, нажимает на маскота и задаёт работу в чате.

## Что передаётся

Ссылка содержит localhost и session ID. Инструкция и скилл не содержат данных макета, HTTP token или pairing code. CLI самостоятельно читает локальную конфигурацию. Не публикуй её, сборку для конкретного компьютера, выгрузки или реальные макеты.

Удалённый cloud-agent не может подключиться к localhost пользователя. Эта установка не добавляет tunnel или облачный relay. Для такой задачи используй агента на том же компьютере.
